ProjectFirma 2.0 / Forms / Textarea

Textarea

Multiline input with optional auto-resize, packaged with its label and help/error text. Form-associated via ElementInternals; emits a composed change event.

Inherited wc import '@esa/ecology/esa-textarea';

Preview

Rows + auto-resize

Set a fixed rows count, or add auto-resize to grow with content up to max-rows.

Sizes

States

Form participation

The element is form-associated. Submitting logs the FormData entry for notes.

API

PropTypeDefaultDescription
label string '' Visible label rendered above the textarea.
size 'xs' | 'sm' | 'md' | 'lg' 'md' Control size.
placeholder string '' Placeholder shown when empty.
help-text string '' Helper text shown below the textarea. Property: `helpText`.
error-text string '' Error message; replaces help text and turns the field red when present. Property: `errorText`.
required boolean false Marks the field required and renders an asterisk on the label.
disabled boolean false Disables interaction.
name string | undefined — Form field name — the key this control submits under.
rows number 3 Initial visible row count.
auto-resize boolean false Grows the textarea to fit content as the user types. Property: `autoResize`.
max-rows number 10 Row cap when auto-resize is on. Property: `maxRows`.
value string '' Current value; mirrored to the form on every input.
minlength number | undefined —
maxlength number | undefined —
autocomplete string '' Autofill hint. The only way to satisfy SC 1.3.5 Identify Input Purpose (AA).
live-error boolean false Announce the error the moment it appears rather than only on focus. Off by default — see the long note on `esa-text-field.liveError` for why (the house pattern is validate-on-submit with `<esa-error-summary>`, and a live region per field races it). Property: `liveError`.

Events

EventTypeDefaultDescription
change CustomEvent<{ value: string }> — Fired on every input. Composed and bubbling; detail.value is the current string.
Binding these events from Angular

Every one of these is a CustomEvent, so the payload is on $event.detail — $event.target.value reads empty, with no error. The names are lowercase and Angular passes them to addEventListener verbatim, so camel-casing one means it never fires.

  • (change)="onChange($event.detail)"

Accessibility

  • Renders a native <textarea> associated to its <label> via for/id.
  • Sets aria-invalid="true" while error-text is present.
  • The required asterisk carries an aria-label="required".
  • Visible focus ring via --focus-ring-* tokens.
